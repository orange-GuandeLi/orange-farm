# 农场尺寸方案（FARM_SIZE）

> 结论先行：**农场大小由 `Boundary` 下 4 个 `CollisionShape2D` 决定，与 `Ground` 铺了多少格无关。**
> `Ground` 只是贴图，铺少了只是露白，铺多了也不影响碰撞。所以"改大"只改 4 个数字 + 重铺 Ground。

---

## 1. 为什么当时"镜头滚不动"

> ⚠️ 2026-11-11 更新：农场已扩到 **120×68**（1920×1088 px），视口 **640×360**（**3.00×3.02 屏**）。
> 当前脚底可活动范围 **x∈[16,1904] / y∈[16,1072]**（118×66 格，自由移动）；四面墙 (960,0)/(960,1080)/(2,540)/(1918,540)，
> Camera `0/0/1920/1088`，出生点 (952,544)（第 59 列 / 第 33 行，正好是正中心格）。
> 下面第 1 节的 20×10 / 320×180 推导与实测保留作历史记录。

当时 `20 x 10` 格 = 脚底可活动 `320 x 160` px，视口 `320 x 180` px。

```
320 / 320 = 1.00 屏（宽）
160 / 180 = 0.89 屏（高）
```

`Camera2D` 的 limit 区域**必须比视口大**，镜头才有滚动余量。一旦 limit 区域某一边
小于视口，Godot 会走"居中"分支 —— 那个轴上镜头**完全锁死不跟随**（见
`servers/rendering` → `camera_2d.cpp:170-190`，实测已确认）。

实测三种情况（当时视口 320×180）：

| limit 区域 | 行为 |
|---|---|
| 672×448（大于视口） | 正常跟随并夹紧，镜头 x∈[160,512]、y∈[90,358] |
| 320×176（小于视口） | **完全不跟随**，镜头钉死在 (160, 88) |
| 320×448（宽=视口） | x 轴锁死，y 轴正常跟随 |

所以"场地太小"= 镜头滚不动 = **必须把农场改到至少 2 屏宽**。

## 2. 通用公式

设农场为 `W x H` 格（tile = 16px）。玩家碰撞盒 `12 x 8`，原点在**脚底**，
所以水平方向要让出 `12/2 = 6` px，垂直方向要让出 `8/2 = 8` px。

### 2.1 四面隐形墙（`Boundary` → 4 个 `CollisionShape2D`）

| 节点 | `position` | `shape.size` |
|---|---|---|
| `FenceTop` | `(16 + 8W, 0)` | `(44 + 16W, 16)` |
| `FenceBottom` | `(16 + 8W, 24 + 16H)` | `(44 + 16W, 16)` |
| `FenceLeft` | `(2, 12 + 8H)` | `(16, 40 + 16H)` |
| `FenceRight` | `(30 + 16W, 12 + 8H)` | `(16, 40 + 16H)` |

推导（以水平方向为例）：
- 墙内沿要留 `6` px 给玩家碰撞盒半宽 → 墙中心 = 内沿 ± `8`（墙自身半宽）
- `FenceLeft` 中心 `x=2`：墙占 `[-6, 10]`，内沿 `10`，玩家脚底最左 `10-6=4`？**不对** —— 见下方校验。

> **校验（实测，不是推导）**：玩家脚底可活动范围恒为
> **x ∈ [16, 16 + 16W]**，**y ∈ [16, 16 + 16H]**。
> 代入 `W=20, H=10` 得 `x∈[16,336]`、`y∈[16,176]`，与当前场景实测值完全一致 ✅
>
> 所以上面的公式里"内沿让出 6/8"已经折算进去了：
> `FenceLeft` 中心 `x=2`、半宽 8 → 墙占 `[-6, 10]`；玩家碰撞盒占 `[foot-12, foot]`… 
> 不对，碰撞盒是 12 宽但**中心在 x=0 偏 0**，即 `[foot-6, foot+6]`，
> 所以脚底最左 `16` 时盒子占 `[10, 22]`，墙面内沿 `10` 刚好贴住 ✅
> 同理垂直：碰撞盒中心 `y = foot-4`，占 `[foot-8, foot]`，
> 脚底最高 `16` 时盒子占 `[8, 16]`，`FenceTop` 内沿 `8` 刚好贴住 ✅

### 2.2 `Ground` 铺贴范围

```
cells cx ∈ [0, W+2)      cy ∈ [0, H+2)
世界覆盖 x ∈ [0, 16(W+2)]   y ∈ [0, 16(H+2)]
```
即比可活动范围四周各多铺 1 格。

### 2.3 玩家出生点（农场正中心）

```
(16 + 8W,  16 + 8H)
```

> 可活动格数是**偶数**时，几何中心正好落在两格的分界线上（W=118 → x=960 是第 59/60 列之间）。
> 取哪一格都行；当前取左格 → `(952, 544)`，落在第 59 列 / 第 33 行。

### 2.4 `Camera2D` limit

```
limit_left   = 0
limit_top    = 0
limit_right  = 16 * (W + 2)
limit_bottom = 16 * (H + 2)
```
正好卡在 Ground 边缘，镜头永远看不到地面以外。

## 5. 施工步骤（以 40×26 为例）

全部在 Godot 编辑器里做，**不要手改 `main.tscn` 文本**（TileSet 里有 1740 个 atlas 坐标，编辑器保存更安全）。

### 5.1 改四面墙

1. 选中 `Main > Boundary > FenceTop`
   - Inspector → **Position** = `(336, 0)`
   - Inspector → **Shape** → `RectangleShape2D` → **Size** = `(684, 16)`
2. `FenceBottom` → Position `(336, 440)`，Size `(684, 16)`
3. `FenceLeft` → Position `(2, 220)`，Size `(16, 456)`
4. `FenceRight` → Position `(670, 220)`，Size `(16, 456)`

> 注意：改 `Size` 时 Godot 可能提示 Shape 资源被多处共享 —— 4 个墙本来各用各的 `RectangleShape2D`，
> 直接改没问题。如果出现"共享资源"警告，选 **Make Unique** 再改。

### 5.2 改 `Ground` 铺贴范围

> ⚠️ 当前 Ground 是 **120×68 = 8160 格**（a/b 棋盘草地），见 §1。
> 铺这么多格不要手刷，用一次性脚本 `tools/paint_checker.gd`：
> 打开 `scenes/main.tscn` → 脚本编辑器打开该文件 → File → Run → 回场景 Ctrl+S。
> 脚本顶部的 `W` / `H` 改成新尺寸就会重铺，规则是 `(x+y)%2` 的 a/b 棋盘。
> ⚠️ EditorScript 只改内存，**必须回场景 Ctrl+S 才会写进 `main.tscn`**（2026-11-10 踩过：跑完发现场景没变）。

### 5.3 挪出生点

`Main > Entities > Player` → Position = `(336, 224)`

### 5.4 设 Camera2D limit

选中 `Main > Entities > Player > Camera2D`：
- **Limit Left** = `0`
- **Limit Top** = `0`
- **Limit Right** = `672`
- **Limit Bottom** = `448`

顺便确认：**Position Smoothing Enabled = 关**（像素风要硬跟随）。

### 5.5 跑起来看

1. 启动游戏，镜头应该**跟随**玩家了
2. 走到农场左上角，镜头应该停在 (0,0) 附近，**不能露出地面外的黑边**
3. 走到右下角，镜头应该停在 (1600, 908) 附近（= limit 减去半个视口）

## 6. 顺手要修的两个既有问题

### 6.1 `TileSet` 的 `source[1]` 是坏的 ✅ 已处理

`source[1]` 原先用 32px 森林贴图 `spr_tileset_sunnysideworld_forest_32px.png`，
但 `texture_region_size` 被设成了 `16x16` → **每棵 32×32 的树被切成 4 块 16×16 的碎砖**。

**现状（2026-11-11）**：该 source 已从 `TileSet_o5qli` 里删掉，现在只剩主图集一个 source。
`Decor` 要用的装饰（灌木 / 小树 / 石墙 / 木栅栏 / 小花）主图集里都有，坐标见 `docs/NOTES.md`。

以后要放大树时，注意**不要新建一个 32×32 的 TileSet**（那会让它跟 16px 世界格子对不齐）：
正确的是在**同一个 TileSet 里**加第 2 个 source，`texture_region_size = (32, 32)`，
但 `TileSet.tile_size` 保持 `(16, 16)` —— 32px 的 tile 会从所在格子往右下方溢出，
再给这个 tile 设 `texture_origin = (-8, -16)` 把树根对准格子底部。

### 6.2 `Decor` 不在 `Entities` 里 → 永远不会和玩家排序 ✅ 已处理

早先 `Decor` 是 `Main` 的直接子节点，而 `Entities` 才开了 `y_sort_enabled`。
按 Godot 的 Y 排序规则（`renderer_canvas_cull.cpp:110-165`）：
**`_collect_ysort_children` 只收集直接子节点**，只有子节点自己开了 `y_sort` 才会递归它的子孙。
所以当时这棵树永远画在玩家**下面**，玩家从树后走过时不会被树遮住。

**现状（2026-11-11）**：`Decor` 已挪进 `Entities` 并开了 `y_sort_enabled`，
所以装饰会和玩家按 Y 坐标互相遮挡。

**遗留的坑**：同一个 `TileMapLayer` 里所有 tile 共享一个 Y 值（整层一个排序值），
所以"逐棵树精确排序"仍然做不到 —— 要精确排序得改成**一棵树一个 `Sprite2D`**，
或者用多层 `TileMapLayer` 的方案。

### 6.3 `Ground` / `Soil` 不需要 `y_sort_enabled`

地面永远在角色下面。`Ground` / `Soil` 都在 `Entities` **外面**，
靠 Main 的树序天然排在玩家前面，`z_index` 保持 0 就行（负 z 会把整层压进别的 z 桶）。
`y_sort_enabled` 开着只会让引擎多做一轮排序，没有收益。可以关掉。
