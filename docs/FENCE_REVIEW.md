# 游戏边界 Review（玩家当前命名为 Fence）

> Review 时间：2026-11-09 12:40
> 审查对象：`scenes/main.tscn` 的 `Fence` 节点组
> **重要前提**：这不是装饰性栅栏，而是**隐形游戏边界**（地图四周的墙）。
> 所有关于"视觉 / Y 排序 / 贴图"的结论，在隐形边界前提下**不适用**。

---

## 一、结论：合并成一个 body 是**正确**的

隐形边界 = 只需要碰撞，不需要视觉。

```
Fence (StaticBody2D)          ← 1 个 body 管 4 面墙
├── FenceTop    (CollisionShape2D)
├── FenceBottom (CollisionShape2D)
├── FenceLeft   (CollisionShape2D)
└── FenceRight  (CollisionShape2D)
```

一个 StaticBody2D 挂多个 CollisionShape2D 是 Godot 的标准做法，
比 4 个独立 body 更简洁（一个 body = 一个边界集合，便于整体启停/复用）。
**这个思路保留。**

---

## 二、上一轮结论的修正

| 上一轮的结论 | 隐形边界前提下 | 说明 |
|---|---|---|
| 🔴 合并 body 导致 Y 排序错乱 | **作废** | 没有视觉 = 没有 CanvasItem 需要排序。Y 排序只影响绘制顺序 |
| 🔴 没有视觉 | **作废** | 隐形边界本来就不该有视觉 |
| 🟢 玩家碰撞盒高 8 导致 8px 缝隙 | **作废** | 看不见墙，就没有"缝隙感" |
| 🔴 玩家出生在碰撞体内 | **仍然成立，必须改** | 见 §三 |
| 🟡 角落 6×8 缺口 | **仍然成立，建议改** | 见 §三 |
| 🟡 可活动区没对齐 16px 网格 | **仍然成立，建议改** | 见 §四 |

## 三、必须改的两处

### 🔴 1. 玩家出生在碰撞体内

**实测：玩家初始 position 不是 (0,0)，被推成了 `(0, -7.94)`。**

`FenceTop` 覆盖 y ∈ [-8, 8]，出生点 (0,0) 的玩家碰撞盒覆盖 y ∈ [-8, 0]，
完全落在墙里 → Godot 第一帧就把玩家挤出去。

→ 出生点挪到农场内部。若采用 §四 的布局，出生点用 **(176, 92)**。

### 🟡 2. 角落有 6×8 缺口

`FenceTop` 覆盖 x ∈ [-10, 330]，`FenceLeft` 覆盖 x ∈ [-16, 0]
→ 区域 **x ∈ [-16, -10], y ∈ [-8, 0]** 没覆盖（右上角对称位置同理）。

玩家碰撞盒宽 12，从场地中心出发四向都实测被挡住，暂未漏；
但玩家在角落出生时可能卡进缺口。§四 的布局已消除缺口。

---

## 四、建议：把边界对齐到 16px 网格

### 为什么现在的边界会"偏"

玩家的碰撞盒是 **12×8，位于原点上方**（`position=(0,-4)`，覆盖 y ∈ [-8, 0]；
实测可见脚底在节点空间 y = +1，与碰撞盒下沿只差 1px）。

所以：
- 玩家**脚底**能停住的位置 = 墙的内沿 ± 玩家碰撞盒的尺寸
- 水平方向：脚底停住线 = 墙内沿 **± 6**（半宽）
- 垂直方向：从北侧撞，脚底 = 墙南沿 **+ 8**（盒高）；从南侧撞，脚底 = 墙北沿 **± 0**

**当前布局的实测结果**：玩家原点可活动范围 x ∈ [6, 314]、y ∈ [16, 180]
→ 308 × 164 像素 = 19.25 × 10.25 格。**不是整数格**，后面铺 TileMapLayer 会错位。

### 实测过的目标布局

假设农场 = **20 × 10 格**（16px 一格），玩家脚底可活动范围正好 x ∈ [16, 336]、y ∈ [16, 176]：

| 形状 | position | size | 覆盖范围 |
|---|---|---|---|
| FenceTop | **(176, 0)** | **(364, 16)** | x ∈ [-6, 358], y ∈ [-8, 8] |
| FenceBottom | **(176, 184)** | **(364, 16)** | x ∈ [-6, 358], y ∈ [176, 192] |
| FenceLeft | **(2, 92)** | **(16, 200)** | x ∈ [-6, 10], y ∈ [-8, 192] |
| FenceRight | **(350, 92)** | **(16, 200)** | x ∈ [342, 358], y ∈ [-8, 192] |

**实测验证**（在测试里摆好后跑四向移动 150 帧）：

```
move_down  → y = 175.9999
move_up    → y = 16.00316
move_right → x = 335.9969
move_left  → x = 16.00316

玩家原点范围: x ∈ [16.003, 335.997], y ∈ [16.003, 175.999]
```

→ 正好是 **x ∈ [16, 336]、y ∈ [16, 176]**（0.003 是浮点误差），即 **20 × 10 格**。
→ 四个角由上下墙与左右墙**重叠覆盖**，**无缺口** ✅

### 为什么墙不是正好贴在 16 的倍数上

因为玩家碰撞盒宽 12、脚底在原点，所以要让**脚底**而不是碰撞盒贴到网格边界，
墙的内沿要往外让出 6px（水平）和 8px（垂直）。
这套数字已经把这点算进去了，**照抄即可**。

## 五、一个思路上的提醒

> **"农场范围"应该由「玩家能站到哪儿」定义，而不是由「墙在哪」定义。**
> 玩家真正能站的地方才是农场。墙是围在外面的东西。

所以先定"农场是 20×10 格"，再反推墙的位置 —— 就是上面那组数。

---

## 六、备选方案：不用物理墙，用代码 clamp

如果后面觉得物理墙难调（推挤感、边缘有微小缝隙），可以换成代码限制：

```gdscript
# 在玩家 _physics_process 里，move_and_slide() 之后
position.x = clampf(position.x, LEFT, RIGHT)
position.y = clampf(position.y, TOP, BOTTOM)
```

| | 物理墙 | 代码 clamp |
|---|---|---|
| 边界精度 | 玩家碰撞盒尺寸决定，有半格偏移 | 精确到像素 |
| 贴墙滑动 | ✅ 自然（move_and_slide 会沿墙滑） | ❌ 停死在墙上 |
| 调试 | 看不见，得开碰撞形状显示 | 数字明确 |
| 代码量 | 场景里配好就完事 | 玩家脚本里加几行 |

**建议现在用物理墙**（你已经搭好了，且滑动手感对俯视游戏更重要），
等真觉得别扭了再换。

# 前瞻 · 镜头限制与农场尺寸（重要）

## 问题

视口是 **320×180**，当前农场只有 **20×10 格 = 320×160**。

`Camera2D` 的 `limit_left / limit_right / limit_top / limit_bottom`
（`limit_enabled` 默认 true，`scene/2d/camera_2d.h:75-76`）用来限制镜头不超出范围。
但源码 `scene/2d/camera_2d.cpp:170-190` 有个分支：

```cpp
if (limit[SIDE_TOP] > limit[SIDE_BOTTOM] - screen_rect.size.y) {
    // 限制区比视口窄 → 走"居中"分支，camera_pos 被固定偏移
    camera_pos.y -= screen_rect.position.y + (screen_rect.size.y - limit[SIDE_BOTTOM] - limit[SIDE_TOP]) / 2;
} else if (screen_rect.position.y < limit[SIDE_TOP]) {
    ...
}
```

代入当前尺寸：纵向 `16 > 176 - 180 = -4` → **为真** → 走居中分支
→ **镜头被固定偏移 6px，完全不再跟随玩家** ❌

横向同理：`limit[RIGHT]-limit[LEFT] = 320` 正好等于视口宽 → 镜头横向锁死，一格都滚不动。

## 结论

> **要能用镜头限制，农场必须比视口大。**

## 实测过的方案：24 × 12 格

脚底范围 x ∈ [16, 400]、y ∈ [16, 208]（384 × 192 像素）：

| 形状 | position | size |
|---|---|---|
| FenceTop | **(208, 0)** | **(428, 16)** |
| FenceBottom | **(208, 216)** | **(428, 16)** |
| FenceLeft | **(2, 108)** | **(16, 232)** |
| FenceRight | **(414, 108)** | **(16, 232)** |

实测：up→16.003 / down→207.9997 / left→16.003 / right→399.9969
→ 正好 **x ∈ [16, 400]、y ∈ [16, 208] = 24 × 12 格** ✅

镜头限制可行性（按源码条件验算）：
```
横向 384 > 320 → 16 > 320-320(0)? false → 正常夹取 ✅
纵向 192 > 180 → 16 > 192-180(12)? false → 正常夹取 ✅
```

对应的镜头设置（`Camera2D` Inspector）：
```
Limit Left   = 16
Limit Top    = 16
Limit Right  = 400
Limit Bottom = 208
```

## 或者

农场就保持 20×10，**不设镜头限制** —— 代价是镜头会看到农场外面（空荡荡的）。
后面往外面画点树/栅栏/水就行（星露谷的农场外面也是有的）。

**两条路都行**，取决于你想让农场多大。建议 **24×12**：既有空间滚动，
又不会大到要铺很多地。
