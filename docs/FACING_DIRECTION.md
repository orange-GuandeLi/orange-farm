# 朝向问题：素材是单一朝向，怎么处理四方向移动

**日期**：2026-11-09
**问题**：往左往右往上下走，人物动画都朝右边
**结论**：**不是你的代码问题，是素材本身只有单一朝向。**

---

## 零、先回答"要不要换素材"

**不用换，现在这个素材完全能用。** 具体理由在 §二 和 §三。

真正需要考虑换素材的时机，是**等你把农场做出来、发现上下移动明显违和**的时候。
而那时候你会发现：把 3 个动画重切成 25 帧只要几分钟，
但**已经写好的游戏逻辑一行都不用改**（因为朝向逻辑是数据驱动的）。

所以：**别急着换，先把游戏做完。**

---

## 一、诊断：素材里根本没有其他朝向

### 实测证据 1：走路 8 帧全部渲染，姿势完全相同

```
[帧0] [帧1] [帧2] [帧3] [帧4] [帧5] [帧6] [帧7]
```

只有腿部在交替，**朝向完全不变**。

### 实测证据 2：脸部像素分析 —— 眼睛偏右

我把 IDLE 帧的头部逐像素打成字符图：

```
  y=29: ..#rrrrrrrrr#.....
  y=30: ..#rrrr#rr#r#....      ← 两只眼睛
  y=31: ..#rrrr#rr#r#....
  列:      43       53
```

```
  脸部左右头发边缘: x=43 和 x=53  → 中点 48.0
  两只眼睛:         x=48 和 x=51  → 中点 49.5
  → 眼睛中点比脸中点右偏 1.5px
```

如果角色是**正面朝向**，两只眼睛应关于脸中点对称（x=46 和 x=50）。
实测在 x=48 / x=51，**明显偏右** → 角色是**四分之三侧视，朝右**。

放大看（20 倍）能清楚看到：头发在左侧较厚、面部和腮红偏向右侧。

### 实测证据 3：持斧动画（动作幅度最大）

```
[帧0][帧1][帧2][帧3][帧4]
[帧5][帧6][帧7][帧8][帧9]
 ↑白色斧头轨迹从左侧扫过    ↑黄色碎石飞向右侧
```

斧头从右后方挥出、碎石向右飞散 → **确认朝右**。

### 实测证据 4：目录里没有任何"朝向"变体

```
Human/WALKING/
├── base_walk_strip8.png       ← 变体是"发型"
├── bowlhair_walk_strip8.png
├── curlyhair_walk_strip8.png
├── longhair_walk_strip8.png
├── mophair_walk_strip8.png
├── shorthair_walk_strip8.png
├── spikeyhair_walk_strip8.png
└── tools_walk_strip8.png
```

**8 个变体全是发型（+ tools），没有一个是朝向。**
20 个动作文件夹全部如此。

### 实测证据 5：源 aseprite 里的图层结构

我从源文件提取出图层名：

```
hand back        ← 手的后层
hand front       ← 手的前层
body / head / eyes / HAIR
bowl hair / short hair / mop hair / spikey hair / afro hair / long hair
```

**关键**：有 `hand front` / `hand back` 这样的**前后分层**，
说明作者在设计时考虑了正面视角的绘制顺序，
但**没有建立 up / down / left / right 四套方向**。

> 补充：源 aseprite 是**加密格式**（文件头 `9b18 0800`，不是标准 aseprite 的 `A5E0`），
> 无法用 Aseprite 打开导出。所以**不能从源文件补出其他方向的帧**。

## 二、关键验证：翻转不会产生偏移

翻转方案能不能用，取决于**角色是否精确居中于贴图**。实测：

```
walk 帧0 角色占 x[43, 53]   中心 = 48.0
贴图宽 = 96                  贴图中心 = 48.0
→ 角色中心与贴图中心一致（flip_h 翻转后不会偏移）✅
```

原理：`centered = true` 时 Godot 以**贴图中心**为翻转轴，
你的角色精确居中在 x=48 → 翻转后**位置纹丝不动**，只是左右颠倒。

> ⚠️ **如果角色不居中**（比如偏移到 x=40），翻转后会跳到 x=56，人物会"抽搐"。
> 你的素材恰好居中，可以放心用。

**另外**：`flip_h` 只影响 X 方向，**脚底线 y=38 完全不变** ——
所以你的 `position = (0, -5)` 对齐**不需要调整**。

## 三、方案：左右翻转 + 上下保持朝向

### 为什么这个方案是标准的

| 移动方向 | 处理 | 理由 |
|---|---|---|
| 向右 | `flip_h = false` | 原图朝向 |
| **向左** | **`flip_h = true`** | 水平镜像，侧视角色左右颠倒**完全合理** |
| 向上 | 保持当前朝向 | 侧视角色往远处走 |
| 向下 | 保持当前朝向 | 侧视角色往近处走 |

**为什么上下不翻**：
这批素材是**侧视**，不是俯视/正面。
上下移动时角色侧身走 —— 视觉上是"侧着身子往屏幕里/外走"。
这在大量独立游戏里是可接受的（玩家主要看的是**移动方向**，不是角色朝向）。

**上下移动时角色不转向**，还有个好处：
玩家按上键时角色不会"突然变脸"，视觉更连贯。

### 代码

```gdscript
extends CharacterBody2D

@onready var animation: AnimatedSprite2D = $AnimatedSprite2D

const SPEED = 80.0

## 记住上次移动的水平方向：-1 朝左，1 朝右。
## 用来决定走路动画要不要水平翻转。
var facing := 1


func _physics_process(delta: float) -> void:
	var direction := Input.get_vector("move_left", "move_right", "move_up", "move_down")
	velocity = direction * SPEED
	move_and_slide()

	# 只在有水平移动时更新朝向。
	# 纯上下移动时保持上次的面朝方向。
	if direction.x < 0:
		facing = -1
	elif direction.x > 0:
		facing = 1

	animation.flip_h = facing < 0

	if direction == Vector2.ZERO:
		animation.play("idle")
	else:
		animation.play("walk")
```

### 三个设计细节

**① 为什么用 `direction.x` 判断**

纯上下移动时 `direction.x == 0`，两个分支都不进 → **朝向保持不变**。
玩家正在往上走时突然变成朝下会很突兀。

**② 站着不动时也保持朝向**

按左走停下后，角色**继续朝左站着** —— 符合直觉。

**③ `flip_h` 的赋值要在动画切换之前**

`play()` 不会改变 `flip_h`，所以顺序无所谓。但把它放在动画逻辑之前更清晰。

**④ `play()` 是幂等的**

重复播同一个动画没有额外开销，**不需要先判断当前是不是别的动画**。

## 四、如果以后想升级素材

### 什么时候值得换

**做完农场地图之后**。判断标准：
- 有了树、房子、篱笆这些环境参照物后，玩家注意力在环境上
- 这时如果还觉得上下移动别扭，再换

### 换素材的成本

| 项目 | 成本 |
|---|---|
| 重新切图 | 25 帧 × 每个动作 30 秒 ≈ 十几分钟 |
| **游戏逻辑** | **零改动** ← 关键 |
| 玩家位置/碰撞 | 只需改 offset 和碰撞体尺寸两个数 |

**因为朝向逻辑是数据驱动的**（一个 `facing` 变量 + 一个 `flip_h` 赋值），
换成四方向素材时，你只要把 `flip_h` 换成"选对应动画名"即可。

### 找素材的关键词

- `4 direction sprite` / `directional character sprite`
- `farm game character sprite 4 dir`
- `top down character sprite sheet`

这类素材通常是：`walk_down.png` / `walk_left.png` / `walk_up.png` / `walk_right.png` 各一份。

### 《星露谷》自己是怎么做的

星露谷的角色是**三向**（正面/背面/侧面）：
- 往下走 → **正面**（能看到脸）
- 往上走 → **背面**（看不到脸）
- 左右走 → **侧面**（其中一个方向靠 flip_h 镜像）

**它的动画文件是分开的三套**，不是靠翻转实现的。
所以想要真正的三向效果，**得找三向素材**。

你现在这批是**纯侧视**，比星露谷少一个维度。
但**侧视 + 左右翻转**是完全可用的方案 —— 只是"往远处走"时看不到背影。

## 五、附带：一个"看起来像背面"的偷懒技巧

有些独立游戏在玩家往**上**走时，用 `flip_v`（垂直翻转）假装是背面：

```gdscript
animation.flip_v = direction.y < 0
```

**我不推荐**：垂直翻转会让角色**头朝下**，非常奇怪。

不过有另一种做法：给"上"方向单独准备一个**只有背面轮廓**的简单素材，
甚至可以用一个纯色的色块代替（很多游戏在角色离屏幕很远时就这么干）。

**但这属于后期优化，现在完全不用管。**
