# 测量手册：怎么把"要改成什么样"变成具体坐标

目标：spec 里每一个坐标、每一个颜色都有出处。凭印象写的坐标会静默出错，
只有把参考图量清楚，改写才是可复现的。

全部命令用 `node <skill目录>/scripts/sheet_probe.js`，前缀简写为 `probe`。

---

## 1. 帧网格

```bash
probe info <png>
```

自动探测帧宽的原理：把"每列的非透明像素数"当列剖面，找它的周期——
真帧宽能让每帧图案精确对齐；再给"内容压在格子边界上"的候选降权。
输出里的候选列表可以直接核对（`P=96(0.75)` 是分数）。

探测不可信时显式指定：

```bash
probe info <png> --cell 96x64
```

**什么时候必须人工确认**：

- 候选 top-2 分数接近（比如 0.75 和 0.73）→ 帧宽可能是 96 也可能是 192，看图确认。
- 参考图是单帧（不是动画）→ 帧数按 1 处理，别硬凑。
- 角色跨格 / 特效溢出格子 → 别套统一网格，按层拆开处理。

验证网格对不对，看 `info` 的"每帧可见范围"：每帧 bbox 应该在**帧内**坐标上落在同样的位置
（比如都在 x43..53），如果每帧 x 位置都在漂，说明帧宽错了。

---

## 2. 调色板：给颜色起名字

```bash
probe info <png> --top 30
```

把颜色按用途归类再写进 `palette`，改配色时只动这一处：

| 类别 | 例子 |
|---|---|
| 肤色 | `#E8AD7D` `#E9AD7D` `#E8AC7D` `#E8AC7C`（同一材质在不同光照下的多个近似色） |
| 衣服 | `#374464` `#252C43` `#384565` |
| 发色 | `#753D3A` `#3E2630` `#BB6D53` |
| 描边 | `#171424` `#181424` |
| 道具/特效 | `#8B9BB4` `#C0CBDC` `#BB6D53` |

注意：同一种材质常有 2–4 个近似色（例如 `#E93245` 和 `#E83145`）。
**改色时要按颜色集合一起改**，漏掉近似色就会留下"脏点"。

---

## 3. 锚点：脚底、中心、身高

从 `info` 的每帧 bbox 就能读出来：

- **脚底 y**：bbox 的最大 y（角色站立的那一行）。
- **中心 x**：bbox 的 x 范围中点。
- **身高**：bbox 的 y 范围长度。

朝向变体必须保持锚点一致，否则角色会跳位。改写后用 `diff` 检查 bbox 是否漂移。

---

## 4. diff 驱动：先找到"最小改动集"

这是整个流程里最省事的一步。**朝向变体、配色变体、"照着另一版改"这类需求，
通常已经存在一个同族参考**（同角色同动作的另一个朝向/另一个版本）：

```bash
probe diff <同族参考.png> <目标素材.png> --list 40
```

输出三样东西：

1. 每帧变化像素数 —— 知道"这个变体一共改了多少"。
2. 颜色转移表 —— 知道"改的是哪几类像素"（例如 `#171424 → #E8AD7D` 就是"眼睛改肤色"）。
3. 坐标清单 —— 直接抄进 spec 的 `fill` 算子。

**同族参考不存在时**（例如要做一个全新的朝向）：

1. `probe find <png> '#XXXXXX' --components` 找到某类像素的连通块 bbox
   （脸通常是"最大的肤色连通块"，注意土块也是肤色但是独立连通块，不会误判）。
2. `probe ascii <png> <frame> --crop x,y,w,h` 看局部结构，确定要盖/要擦的范围。

## 5. 朝向变体的通用配方

以"朝下 → 朝上"为例（换成朝左/朝右，把 mirror 插进去）：

| 要量什么 | 怎么量 |
|---|---|
| 头顶保留几行 | 比较 A/B 两版同一区域，找**第一行不同**的位置：以上是共用的头顶，以下是要换的部分 |
| 后脑长什么样 | 直接取朝上参考帧对应区域的像素 |
| 头发相对头骨的偏移 | 同一张图里量：头发 bbox 左上角 − 头骨 bbox 左上角 |
| 眼睛/腮红/胸口色块在哪 | 按颜色找 + 连通块定位，逐帧坐标会变，所以 spec 要逐帧写 |

把这些量写进 spec 时：

```jsonc
{ "frame": 0, "ops": [
    { "op": "copy", "src": "dig_base", "frame": 0 },          // 先整帧复制
    { "op": "fill", "rect": [48, 30, 1, 2], "color": "skin" }, // 再逐个色块改写
    { "op": "fill", "rect": [51, 30, 1, 2], "color": "skin" }
] }
```

头发层是另一个图层：保留头顶 → 擦掉不该有的部分 → 贴上后脑。

```jsonc
{ "frame": 0, "ops": [
    { "op": "copy", "src": "dig_hair", "frame": 0 },
    { "op": "clear", "rect": [0, 28, 96, 36] },
    { "op": "copy", "src": "idle_hair_n", "frame": 0, "rect": [42, 28, 13, 6], "at": [42, 28] }
] }
```

## 6. 验收：改了多少 + 保留了多少

改写类需求要同时给出两类数字：

```bash
probe diff <原图.png> <产物.png> --expect 117          # 改了多少
probe find <产物.png> '#8B9BB4' --components            # 该保留的还在不在
```

"必须原样保留"的典型对象：

- 特效残影（灰色 `#8B9BB4` 之类）—— 有意为之的运动模糊，不是脏点。
- 地面/掉落物（土块 `#BB6D53`）—— 属于动作的一部分。
- 描边（`#171424`）—— 轮廓线，颜色不能变。

校验标准应该是**具体数字**：每帧改 N 像素、全图共 M 像素、保留项计数不变。
写不出数字，说明改写过程里混进了没量过的东西。

## 7. 一个真实例子（可直接对照数值）

农场项目的"朝上挖掘"：13 帧 × 96×64 的条带。

| 量 | 值 | 来源 |
|---|---|---|
| 帧网格 | 96×64 × 13 | `probe info` |
| 每帧角色 bbox | x43..53 y23..38 | `probe info` |
| 改动总量 | 117 px（每帧 9 px） | `probe diff --expect 117` |
| 改色规则 | 眼睛 `#171424`/`#181424`/`#181525` → `#E8AD7D`（52 px）<br>腮红 `#FA717A` → `#E8AD7D`（26 px）<br>胸口 `#E93245`/`#E83145` → `#374464`（39 px） | `probe diff` 的颜色转移表 |
| 保留项 | 灰色残影 `#8B9BB4` 182 px、土块 `#BB6D53` 10 px | `probe find` |
| 头顶保留行数 | 8 行（split 行 = 28） | 比较 `bowlhair_idle_s` / `_n` 的第一行差异 |

注意眼睛颜色有 **3 个近似色**（52 px = 每帧 4 px × 13 帧）——只改其中一种会留下 26 个黑点。
这就是第 2 节说的"按颜色集合一起改"。
